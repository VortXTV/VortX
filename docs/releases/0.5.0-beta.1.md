# 0.5.0 Beta 1 - Native core, Cinema, and durable watch state

**Draft for release review — not published or ready to install.** These notes describe the source candidate since [0.4.0 Beta 21](https://github.com/VortXTV/VortX/releases/tag/v0.4.0-beta.21), with the unfinished gates called out below. Native shipping selection, both native/web add-on adapters and the reviewed initiating playback repairs are integrated. The matching website source, including its final manifest-admission repair, has passed independent source/security review and is deployed with production asset/CSP readback. Native Usenet wiring still has concrete implementation blockers; final SDK, whole-app and package verification also remain pending. Source identity is **0.5.0**, Apple build **260** and Android version code **241**, advancing the published build **259** / code **240**. This is not yet a receipt for packaged or installed versions.

**Update every device using the same VortX account when the final packages are published.** The 0.5 candidate brings VortX's own native account and streaming core, a more consistent Cinema experience on Apple and Android, durable profile and Watchlist edits, history-preserving migration, and further repairs to episode preparation, pause/resume and subtitles. Your existing player controls, integrations, downloads and add-ons remain part of the release; the interface work is not a feature reset.

## What's new

**VortX has its own native account, catalog and streaming path.** The new core handles profiles, add-on resources, catalogs, metadata, sources, subtitles, library membership, Continue Watching and viewing history through the app's existing surfaces. The native-only Apple package path omits the retained Stremio core and embedded Node runtime; Android's native package path omits its legacy core library too. Full Apple builds use the native in-process streaming server, while Mac uses a separate native daemon. Lite keeps its no-embedded-server boundary. Optional Stremio account connection remains a separate supported integration rather than becoming your VortX sign-in. Shipping configuration now selects the native path by default; actual final package content must still pass its release gates before publication.

**Account changes are committed before the interface reports success.** Native changes are written to an encrypted account checkpoint and read back before their resulting state is published. Profile, add-on, watched and Watchlist operations retain the account and profile that initiated them. A late response from a signed-out account or an older profile cannot populate the newly selected viewer. An uncertain write enters recoverable state instead of allowing later edits to overwrite an unknown result; reopening checks the persisted state before accepting more mutations. Offline opening uses an authenticated existing checkpoint, rather than inventing an empty account when a cloud request is unavailable.

**Concurrent sync uploads advance from the cloud revision they actually merged.** An older device previously could prepare an upload against stale cloud data, give it a later wall-clock revision, and overwrite another device's accepted edit without causing a conflict. Apple and Android now propose exactly the merged base plus one, or a create-only initial revision for an authenticated absent record. A rejected write must pull and merge again before retrying; neither a clock value nor the rejection's version echo can promote stale data. Existing account-generation, encrypted checkpoint and pending-edit acknowledgement guards remain in place. This repairs the reproduced production-manager lost-update path; deployed cloud and physical multi-device acceptance still remain.

**Profiles can keep their own streaming account without borrowing another viewer's history.** Shared-account and independent-account profiles retain separate credential and resource authority. Connecting or replacing a profile's streaming account requires the verified account identity and accepted account revision. Old history and add-on state from account A cannot be relabelled as a newly connected account B. Dashboard edits remain sparse: changing a name or appearance preserves unrelated settings and account bindings. Selecting the active viewer remains local to each device.

**Watchlist is a real want-to-watch list, separate from saved Library and viewing history.** Both native hosts store membership per title and profile, commit the captured operation, then confirm the resulting membership before updating its button. Removals retain their own records so an older peer list cannot silently add the title back. Existing authenticated lists seed only missing titles and do not override newer edits or removals. Adding beyond 1,000 titles reports a capacity limit instead of deleting an older title. Android's integrated gateway also checks the captured register revision, rejecting an older edit even within the same account and profile. Cross-language fixtures check the shared item representation; physical cross-device convergence remains a final acceptance check. Remote Trakt/SIMKL lists keep their own existing behavior.

**Previously watched episodes are migrated from evidence, not guessed.** Some older accounts store watched episodes as compressed bitmaps rather than explicit episode IDs. The new migration decodes them against episode inventories from the original configured provider, tied to the exact account, profile, verified user, source and row. It retains the original encrypted snapshot and accepted evidence. If that original provider is unavailable or ambiguous, history remains visibly pending with a Retry action instead of being converted to empty history or fabricated progress. Historical retry continues to use the original source even if the current account configuration has changed; recovered history cannot be imported into the replacement account. Both Apple and Android journal/retry hosts are integrated. A pending independent-account connection preserves the currently active binding and can resume after restart using its exact retained credential transaction.

**Cinema keeps the useful routes together.** Apple Home, Browse/Search, Library, Watchlist, History and Downloads use a consistent hierarchy on iPhone, iPad and Mac. Quick View exposes Watch Now, Add to Watchlist and Details without hiding its actions below the initial phone viewport. Catalog and Continue Watching cards retain artwork, ratings, facts and synopsis; episode details retain their fuller metadata. Source badges wrap on narrow phones, and source groups stay readable when you jump between add-ons. Mac retains horizontal navigation, a visible Search field, native close/minimize/zoom and one detail Back.

**Android touch and TV gain the same Cinema navigation structure.** Featured Home and Browse can share a destination while preserving the separate-Browse preference. See All opens the selected Home row, including client-generated rows and paging. Library exposes Downloads, Watchlist and Previously Watched routes without replacing saved membership with playback history. Continue Watching cards keep a typed, one-shot resume action and fall back to Details when that device has no matching saved stream. Android TV restores the invoking shelf or Library entry when returning from a depth route, and its ordered source tabs jump to the chosen add-on section while retaining nearby groups. The combined production-source cohort compiles and passes its focused tests; final optimized package compilation and physical D-pad/focus acceptance remain release gates. Isolated source fixtures do not establish every TV interaction.

**Each profile can control which add-ons it sees and how their sources rank.** The per-profile visibility and ranking settings inherit the account defaults until that viewer explicitly changes them. Disabled add-ons remain scoped to that profile; accepted configuration changes retain the captured account and profile. Reordering or replacing add-ons is committed as one ordered change, and a failed or stale operation cannot publish a misleading successful list.

**Website add-on edits have a durable, account-bound acknowledgement path.** Deliberate install, remove and reorder actions now have a versioned causal contract with the native core and both hosts. The hosts checkpoint the exact event and its matching receipt before acknowledging it; an old baseline or a receipt belonging to another account/profile cannot stand in for the submitted edit. A newer native removal or account change remains a visible conflict instead of being presented as successful restoration. Unsupported or rejected work stays pending without blocking independent valid changes. The reviewed matching website uses native state as its authority after migration, rather than the preserved legacy list. It also checks known optional manifest fields before queueing a descriptor the native decoder cannot consume, while retaining valid defaults and unknown extensions. The matching source is deployed and its production assets are verified; authenticated multi-device convergence and live Stremio-account import are still separate acceptance checks.

## What's fixed

**Continue Watching prepares the next episode for the exact viewer and episode.** Apple now connects Continue Watching episode navigation to bounded next-episode source preparation. The work captures the active profile, account, episode, source generation and chosen release before it waits. Leaving the route, switching viewer, changing source or replacing the account retires the old result. The next episode can reuse a valid prepared source; an expired or superseded preparation is rejected before loading. Host-side preparation and admission are bounded. That does not complete native NNTP operation leases and propagation of caller cancellation; those client paths remain implementation gates below.

**A fresh show starts with regular episodes rather than specials.** The default Play target and initial episode-list season now prefer season 1 or the first regular inventory instead of the season-zero special that happens to sort first. A manually selected special, an exact Continue Watching target and a resumed special remain authoritative. Shows containing only specials still work. This addresses the default-selection part of [#244](https://github.com/VortXTV/VortX/issues/244); it does not establish automatic watched tracking after returning from Infuse.

**Binge playback remembers the audio language actually selected.** Accepted in-player audio changes update the captured series choice. Next-episode selection and warming prefer a compatible source while retaining the chosen add-on/release tie-break. A delayed track inventory from an outgoing load cannot teach the next episode the wrong language. If compatible metadata is unavailable, preparation can defer or fall through to allowed alternatives rather than silently presenting an incompatible warmed choice as confirmed.

**Pause survives an accepted source or player replacement.** A same-media replacement carries the viewer's paused choice into the newly mounted engine. Old recovery callbacks cannot turn it into an unsolicited Play, and a rejected replacement does not alter the current player. A newer explicit Play, a different episode or an obsolete mount cannot inherit the previous pause handoff. Existing preview return continues to restore the original owned position and pause choice.

**A pending seek keeps its accepted target through recovery.** AVPlayer recovery retains the target that the current seek actually owns instead of losing it during a slow reopen. Queued mpv property/restart samples are fenced to the issued source and generation; an optimistic reported target is not treated as completed playback recovery. Manual seeking continues to retire an older automatic resume. Resume at zero and the opening seconds of local NNTP playback retain their real ownership and position rather than being converted into a generic restart.

**Native Dolby Vision startup on Apple TV gets its actual decoding window.** A retained TV diagnostic revealed an initiating timing defect: loading the MP4's display metadata took over ten seconds, and the old ten-second startup timer demoted AVPlayer in the very same instant its item finally attached. The item never received an opportunity to decode. Metadata preparation now has its own bounded deadline and same-item attachment without fabricated display criteria if that deadline expires. The unchanged ten-second active decoding allowance begins from the exact item's real attachment, not from the earlier metadata request. Late metadata, an old source, terminal failure or Stop cannot reattach the retired item, and pause intent is preserved. This repairs that corroborated pre-attachment race, not every Dolby Vision rejection or stream stall.

**mpv cache recovery reads the native cache state that actually exists.** Cache statistics are now decoded from libmpv's typed cache-state map. The previous slash-property reads returned unavailable on the pinned player, hiding the low-level seek counter and preventing some bounded memory-pressure recovery from being admitted. A reanchor now requires the actual native counter and current source, command and pause ownership; an optimistic position alone cannot confirm it. The recovery remains bounded, preserves pause and restores the original cache option after success, rejection, cancellation or timeout. This fixes the measured cache-state/admission defect without changing decoder policy or promising unlimited throughput.

**mpv preserves complete request-header values when switching sources.** Commas, quotes and backslashes in sanitized add-on headers no longer pass through a comma-separated option parser that can split a single field. The player sets a typed header array in deterministic order and clears fields that do not belong to the next source. Final header admission happens before retiring the current source's load, pause, cache-recovery or display bookkeeping; a rejected header option does not dispatch the replacement. This repairs the reproduced property/admission path, not a claim that every redirected AIOStreams or TorBox stream, hardware decoder or HTTP range response is fixed.

**Terminal errors cannot restart an old item underneath the error screen.** Apple TV recovery now also fences queued property callbacks after terminal failure. Retry remains tied to the episode that failed to resolve, including timeout, duplicate outgoing-source and rejected-command cases. Later native recovery work cannot dismiss the useful error or quietly start the previously played episode. Explicit Dolby Vision-remux Off still takes precedence over display defaults and remote configuration.

**Subtitle background choices affect the actual mpv subtitle renderer.** The existing background styles now drive the rendered subtitle box instead of being only an interface preference. Track selection, timing, styling, file-matched add-on subtitles, pinned transport and native overlay behavior remain available. Player accent controls stay inside their control shapes, and Reduce Transparency gives those controls an opaque presentation.

**Paused external captions stay on the source timeline after remux resume.** Activating an external subtitle or changing its sync offset now immediately refreshes the cue using the achieved remux origin, not just the replacement player's local clock. The right cue appears while paused without waiting for a periodic tick, seeking or resuming playback. Direct native playback retains its zero-origin behavior, and native subtitle fallback remains untouched while external captions are off.

**An explicit Stremio reconnect can restore deliberately imported add-ons.** On Apple, owner and shared-account sign-in now imports the authenticated account's add-ons additively into the native roster, including a previously removed same-URL add-on, rather than only updating the account model. The import retains the selected account, profile, credential and source authority through its durable commit. Passive authentication/recovery does not perform that explicit import and must not resurrect removed add-ons. If the connection saves but the import cannot be confirmed, the app reports that distinction and asks for refresh/retry rather than claiming success. This repairs the native explicit-import path behind [#205](https://github.com/VortXTV/VortX/issues/205); final account/device acceptance remains separate.

**Native NNTP read-ahead now works concurrently at the actual media boundary.** The identified bottleneck was in the logical media pump: it acquired articles serially through small reads even though the underlying session supported concurrent work. It now warms bounded article batches through the same single-flight and validation path. A seek cancels the older warming generation before waiting for the new read, and stale completions cannot restart it. Nearer useful playback coverage is kept ahead of farther speculative articles; cold archive caches are reclaimed before recently used playback caches; contiguous cached coverage stops at a real hole. The unchanged four-connection default keeps background work bounded and leaves headroom for a foreground read under the unchanged memory budget. This repairs the proven scheduling defect, not the still-incomplete native host/indexer wiring or a claim that every NNTP provider or connection can sustain every bitrate.

**Apple NZB eligibility uses the selected runtime instead of requiring a legacy listener.** The integrated admission gate lets a supported native Full target attempt bounded local startup with configured saved providers or validated add-on server hints, even before its native endpoint has been published. It does not borrow a legacy listener when native mode is selected, start a process while ranking sources, or make Lite/missing-runtime local playback appear available. The existing remote TorBox path remains independent. This fixes source eligibility; operation leases, cancellation and selector wiring still need the completion gates below.

**Local NNTP starvation recovery is bounded on Apple TV.** The player distinguishes genuine repeated starvation from ordinary buffering and uses same-source recovery with the retained resume target. It does not repeatedly erase useful cache or restart forever. The native transport tests exercise cancellation, foreground admission, socket reuse, exact range/EOF bytes and retirement. Compressed or encrypted archive reconstruction and PAR2 repair remain unsupported; larger buffering settings do not change those limits.

**Fresh MPV/FFmpeg build inputs replace the old dependency package.** The selected Apple MPVKit artifact has rebuilt FFmpeg 9 libraries, the retained Dolby Vision split capability, and Apple SecureTransport for HTTPS. It also includes the reviewed Mac CoreAudio initialization-failure lifetime repair: failed setup no longer leaves device listeners pointing at an already released output context. Artifact checks cover the required Apple slices, architectures, deployment floors and linking dependencies. These are dependency/content and lifecycle repairs; Dolby Vision output, audio routing and decoder behavior still need the final app and physical display/receiver checks.

## Retained from Beta 21 and earlier

The source retains profile creation/edit propagation across Apple, Android and the separately deployed website; chosen add-on/release continuity for Next/Previous, preloading and batch downloads; account-owned add-on removals and order edits; downloaded-episode resume; terminal-error Retry; manual-seek authority; preview return; and the repaired Mac Search and window controls. See the [Beta 21 notes](https://github.com/VortXTV/VortX/releases/tag/v0.4.0-beta.21) for their full behavior and limits.

Apple retains the iPhone/iPad startup repair, compact touch player, all fourteen real seek-bar styles, pinch Fit/Fill, chapters, tracks, subtitle timing and styling, skip-times editing, configurable intro/credits countdown with Off and Cancel, source/player switching, external-player handoff, background playback and supported AVPlayer Picture-in-Picture. Search, Discover, Library, ratings, where-to-watch, collections, profile selection, pairing, diagnostics and integration settings remain reachable. Trakt/SIMKL, live TV, offline downloads, watched-download controls, Newznab/NZB indexers and multiple ordered NNTP servers are retained. Full/Lite server boundaries remain explicit.

Android retains accounts and encrypted sync, profiles and who's-watching, catalogs and source filters, debrid, the detailed player controls, subtitles and audio selection, skip editing/countdown, background playback, Picture-in-Picture, local previews, live TV, torrent serving, offline downloads and retry, Google Cast, external-player handoff, Trakt/SIMKL, Newznab/NZB indexers, ordered NNTP servers, list imports, Home rail preferences and the signed configuration layer. Full keeps mpv with Media3 fallback; Play keeps Media3 without the GPL player libraries. The new presentation and native migration do not certify one-to-one Apple/Android feature or visual parity.

## Verification and remaining release gates

The revised native/web add-on contract passed **344 targeted native tests** and complete-workspace CI on both Linux and macOS; the reviewed source is now pinned by the app workflows. Both host adapters are integrated: Apple's five actual-native suites passed against that input, including explicit owner/shared-account import and passive-removal protection, and Android's matching cohort passed **194/194 tests with zero skips**. A freshly built earlier library also passed the callable C ABI gate, but its bytes do not establish the final revised SDK/package gate. The scoped native transport change passed **27 targeted tests**, including a regression that fails on the original serial implementation and observes three concurrent article requests after the fix. Its large archive fixture retained the existing connection threshold and stayed under the unchanged accounted-memory cap. This is synthetic transport evidence, not live provider throughput, process-memory or physical playback proof.

Focused Apple source/identity/terminal fixtures passed, including **22 independent new-show default-selection checks**. A fresh silent local-media run passed **16/16 AVPlayer seek-producer checks**, and the overlapping-mpv-seek fixture observed native restart settlement on the fresh player. The new native-DV preflight regression passed **17/17 production-method checks** with inert AVFoundation doubles and a real ten-second uncooperative metadata deadline; the old source failed nine behavioral assertions. The actual fresh mpv library also returned the cache counter unavailable through the old slash reader and available through the new map reader, then advanced it during a paused synthetic reanchor while restoring the original option. Header handling passed fresh-player property checks plus **33/33 actual extracted admission checks**; paused subtitle-clock handling passed **14/14 actual-method checks** and the recovery cohort. These exercise recorded producer/seek/cache/header/caption behavior without an installed app, provider account or audio-output test; they do not certify sustained playback or display switching on physical hardware. The isolated Cinema renderer produced inspected native iPhone/iPad captures for its recorded Home/Search/source/Quick View surfaces. It does not run the production account, Watchlist mutation, provider or player workflows. A full native Mac Debug compile passed after repairing an app-owned account-model reference; that used the existing reviewed SDK for compilation, not the new final release package. Android's earlier combined production compilation and focused Native/Cinema/Watchlist/account/TV-source cohort passed **528/528 tests** across Full and Play, with no skipped tests. Watchlist also has passing standalone and cross-language canonical fixtures. Nine actual Gradle configuration checks cover native defaults, environment/property precedence, blank comparison flags and invalid combinations without substituting for final APK/AAB inspection.

Apple's production-manager paired-base sync cohort passed **18/18 checks**. Android's actual-manager native cohort passed **40/40 checks** and its explicit legacy-manager compatibility cohort passed **52/52**, with no failures, errors or skips; the original epoch-based overwrite was reproduced before the repair. These manager tests use the actual crypto/native boundary and a synthetic strict-newer service, including rejected writes, fresh pulls, peer preservation and retry ownership. The separate encrypted Swift/Kotlin carrier fixture passed exchanges, cold checkpoint reopening, profile/add-on/history/Watchlist convergence and stale-peer cases using real native sessions and production AES-GCM with a synthetic account/key. Its conflict recovery is a manual fresh pull/merge/upload, and must not be counted as production-manager automatic-retry proof. No deployed cloud-account or installed cross-device synchronization was performed by these fixtures.

An earlier Android candidate's actual Full APK/AAB and Play debug package passed version, native-selection, three-ABI, callable-export and legacy-library-omission readback. Full positively contained mpv/FFmpeg and its APK/AAB passed the pinned production-signing gate; Play debug excluded the GPL player libraries but remains a debug-signed diagnostic package. Those bytes precede the later source repairs and do not supply the final tagged Play release, immutable release provenance or checksum/feed receipt. The earlier Apple candidate built all five SDK slices but stopped at a non-executable independent ABI verifier, before app/package compilation; the script-mode regression is repaired in source and requires a fresh candidate.

The subsequent Android candidate completed CI successfully, but its owner's actual artifact readback is still pending. The subsequent Apple candidate passed the repaired ABI gate and compiled its tvOS simulator app, then failed the fail-closed launch smoke gate on a UTF-8 decoding error; simulator launch acceptance and publication were not established. Both candidates used the older app/native inputs, not the later Apple admission/diagnostic and native article-deadline revisions, so neither supplies final revised package acceptance.

**Seek diagnostics retain native evidence without inventing a stall fix.** The integrated mpv diagnostic change passed **32 actual property/wiring checks** and records seekability, demuxer byte position, source size and the native codec profile under the current source/command ownership. Unavailable or malformed properties remain labelled as such. Demuxer position is not an HTTP request offset or returned Content-Range, and these diagnostics do **not** resolve the original nonzero-offset freeze or prove a hardware-decoder cause.

**Website source and production deployment accepted:** the final native-authoritative projection, causal edit path and bounded optional-manifest admission repair passed independent source/security review, **128/128 Node tests**, and the Astro build/CSP gate covering **19 pages and seven script hashes**. That supersedes the earlier 126-test website freeze. Its normal main-branch merge has the exact reviewed source tree, and the successful production deployment was read back at the public domain and deployment origin: all nine reviewed JavaScript bundles match byte-for-byte, with the 19 HTML pages and seven-hash CSP verified. This establishes deployed source/content, not authenticated multi-device sync, live Stremio credentials or provider/device playback. The DV pre-attachment, mpv cache-map/header and caption repairs are integrated in app source, but their final whole-app build and device acceptance remain pending.

**Native Usenet still has source-level blockers, not just device tests.** Apple's selected-runtime eligibility repair is reviewed and integrated, but native operation-lease/cancellation and selector-client wiring remain unfinished. Android's new captured-owner admission overload is only an API step: complete native NNTP routing still needs to preserve add-on providers/mirrors and replace the old Kotlin route. Direct indexer wiring is not accepted; its first cohort exposed two older-owner retirement failures now under repair. Per-job server-UUID cancellation, explicit selection and archive selectors using the original item ordinals remain under implementation/testing. These are required migration/retained-functionality repairs, not features removed from scope.

The separate reviewed native transport repair admits all sixteen saved providers and passed **21 targeted NNTP tests**. Its reviewed follow-up now bounds the complete article request—including memory/socket queues and all provider fallback attempts—by one deadline, rather than resetting the budget per provider. The actual request-path baseline failed five of eight deadline regressions; the revised full cohort passed **29/29**. Neither revision has a fresh packaged SDK yet. These synthetic production-path checks do not complete caller-operation/client wiring or establish real-provider throughput.

**Pending before this draft becomes a release:** complete and independently review those native Usenet host/indexer/resolver repairs, bind freshly built SDK/server inputs to the final reviewed native source, then complete optimized whole-app and simulator/package gates covering the integrated account and playback repairs. Verify actual packaged versions, callable native libraries, legacy-runtime omission, deployment floors and production signing, followed by checksums, immutable provenance, release assets and update feeds. Source build/code **260/241** passes the monotonicity check against the current release; the final IPA/DMG/APK/AAB metadata still needs separate verification.

**No blanket issue or playback closure is claimed.** The refreshed open reports include repaired subproblems, older unconfirmed reports and substantial feature requests; a matching title or passing helper does not resolve the whole issue. Sustained Dolby Vision pause/seek/stalls or fallback, redirected AIOStreams/TorBox HTTP EOF, nonzero-offset freezes, provider-specific NNTP buffering, frame pacing, receiver output, overnight playback and full cross-device account convergence still require current artifact/device receipts where no initiating defect has been reproduced. The immediate-launch/player-init crash reports also need a current crash stack and exact build. Library membership, local Watchlist, remote integration lists and viewing history remain distinct; success in one is not proof that the others synchronized.

**Several requested features remain unfinished in this beta.** Infuse handoff does not establish watched completion or automatically suggest the next episode on return. Apple Picture-in-Picture still depends on an accepted AVPlayer path; mpv fallback does not gain PiP from the remux repairs. A full Local/Trakt/SIMKL rail-source selector, remote cross-device download control, meaningful source-similarity thresholds, broader SIMKL calendar/recommendation/rewatch/custom-list features and Windows support are not claimed here. Library genre grouping and the complete advanced Discover/filter bundle remain separate work. These remain part of the active overall goal, not discarded requirements or features declared complete by publishing a beta. The Cinema changes do not close every broad Android parity request.

## Please test after publication

- Update all devices using one VortX account. Create/edit a profile from the app and website, then confirm the full record arrives without changing each device's selected viewer. Switch between shared and independent-account profiles and check that add-ons, history and Watchlist stay with their owners.
- Install, remove and reorder add-ons from the updated website and an app. Confirm a rejected or conflicting edit stays visible and does not resurrect a newer removal. On Apple, explicitly reconnect a Stremio owner/shared account to import its add-ons; ordinary app reopening must not perform that explicit re-import.
- Add and remove different Watchlist titles on two updated devices. Confirm both edits converge, a removed title does not return from an older list, and the saved Library and watching history remain separate. Test a queued operation followed by a profile/account switch.
- Check previously watched shows after migration. If history is pending, use Retry and verify that unresolved data remains retained when its original provider is unavailable; the generic notice should not expose private account/source identifiers.
- Open a fresh show with specials, then open an explicitly selected or resumed special. The default should begin regular episodes; the exact special should still open as requested.
- Choose an add-on/release and actual audio language, then try Continue Watching, preloading, Next/Previous and a failed candidate. Pause before changing source or player; confirm the accepted replacement stays paused at the correct position.
- Resume at zero and near the start, manually seek elsewhere, and wait past the old recovery interval. An old automatic target must not take over. Fail an episode resolution, then Retry and confirm it remains the failed episode.
- Check Cinema Search, See All, Library/History/Watchlist/Downloads, Quick View and episode/source controls on phone, tablet, Mac and Android TV. On TV, check focus restoration, add-on source tabs and Back during a slow handoff.
- Try the subtitle background styles, timing and language choices. After a remux resume, pause and activate an external subtitle or change its delay; the cue should refresh at the source position without resuming playback. For native NNTP and header-dependent sources, record source, seek/pause actions and buffering diagnostics. Export Diagnostics promptly with the final build, device, episode, add-on/provider and preceding action if playback is blank, stalled or starts at the wrong point.

## Install — planned assets, pending package verification

The platform floors remain **iOS 16, tvOS 18 and macOS 14**. Final filenames and versions must be checked against the published assets; nothing in this draft is a download receipt.

**Apple TV.** Planned Full and Lite IPAs are `VortX-tvOS-v0.5.0-beta.1-ci.ipa` and `VortX-tvOS-lite-v0.5.0-beta.1-ci.ipa`. They require your usual sideloading/signing service.

**iPhone and iPad.** Planned `VortX-iOS-v0.5.0-beta.1-ci.ipa`; both devices use the same IPA. The distribution IPA is unsigned and must be re-signed. [Apple installation guide](https://github.com/VortXTV/VortX/wiki/Installing).

**Mac.** Planned `VortX-macOS-v0.5.0-beta.1-ci.dmg`, an Apple Silicon package with a matching arm64 native daemon. It is not a universal Intel build or a notarized distribution. [Mac installation guide](https://github.com/VortXTV/VortX/wiki/Install-on-Mac).

**Android.** Planned `VortX-0.5.0-full-mpv-universal.apk`, `VortX-0.5.0-play-media3-universal.apk` and matching Play `.aab`. Each APK serves phones and Android TV with arm64-v8a, armeabi-v7a and x86_64; the filename selects the player engine, not the device type. The AAB is a distribution bundle, not an installable APK. Actual signer/provenance and checksum manifests must accompany the accepted packages.

The public release, in-app updates and [AltStore / SideStore source](https://vortx.tv/altstore.json) are updated only after the protected publication gates pass. Preserve your existing installation and sign-in until those final assets are available.
