# 0.5.0 Beta 1 - Native core, Cinema, and durable watch state

**Draft for release review — not published or ready to install.** These notes describe the source candidate since [0.4.0 Beta 21](https://github.com/VortXTV/VortX/releases/tag/v0.4.0-beta.21), with the unfinished gates called out below. Native shipping selection, both native/web add-on adapters, the Usenet host changes and reviewed initiating playback repairs are source-reviewed and integrated, with the combined canonical Apple and Android cohorts accepted. The matching website source, including its final manifest-admission repair, has passed independent source/security review and is deployed with production asset/CSP readback. Fresh SDK, whole-app and package verification remain pending. Source identity is **0.5.0**, Apple build **260** and Android version code **241**, advancing the published build **259** / code **240**. This is not yet a receipt for packaged or installed versions.

**Update every device using the same VortX account when the final packages are published.** The 0.5 candidate brings VortX's own native account and streaming core, a more consistent Cinema experience on Apple and Android, durable profile and Watchlist edits, history-preserving migration, and further repairs to episode preparation, pause/resume and subtitles. Your existing player controls, integrations, downloads and add-ons remain part of the release; the interface work is not a feature reset.

## What's new

**VortX has its own native account, catalog and streaming path.** The new core handles profiles, add-on resources, catalogs, metadata, sources, subtitles, library membership, Continue Watching and viewing history through the app's existing surfaces. The native-only Apple package path omits the retained Stremio core and embedded Node runtime; Android's native package path omits its legacy core library too. Full Apple builds use the native in-process streaming server, while Mac uses a separate native daemon. Lite keeps its no-embedded-server boundary. Optional Stremio account connection remains a separate supported integration rather than becoming your VortX sign-in. Shipping configuration now selects the native path by default; actual final package content must still pass its release gates before publication.

**Account changes are committed before the interface reports success.** Native changes are written to an encrypted account checkpoint and read back before their resulting state is published. Profile, add-on, watched and Watchlist operations retain the account and profile that initiated them. A late response from a signed-out account or an older profile cannot populate the newly selected viewer. An uncertain write enters recoverable state instead of allowing later edits to overwrite an unknown result; reopening checks the persisted state before accepting more mutations. Offline opening uses an authenticated existing checkpoint, rather than inventing an empty account when a cloud request is unavailable.

**Concurrent sync uploads advance from the cloud revision they actually merged.** An older device previously could prepare an upload against stale cloud data, give it a later wall-clock revision, and overwrite another device's accepted edit without causing a conflict. Apple and Android now propose exactly the merged base plus one, or a create-only initial revision for an authenticated absent record. A rejected write must pull and merge again before retrying; neither a clock value nor the rejection's version echo can promote stale data. Existing account-generation, encrypted checkpoint and pending-edit acknowledgement guards remain in place. This repairs the reproduced production-manager lost-update path; deployed cloud and physical multi-device acceptance still remain.

**Profiles can keep their own streaming account without borrowing another viewer's history.** Shared-account and independent-account profiles retain separate credential and resource authority. Connecting or replacing a profile's streaming account requires the verified account identity and accepted account revision. Old history and add-on state from account A cannot be relabelled as a newly connected account B. Dashboard edits remain sparse: changing a name or appearance preserves unrelated settings and account bindings. Selecting the active viewer remains local to each device.

**Watchlist is a real want-to-watch list, separate from saved Library and viewing history.** Both native hosts store membership per title and profile, commit the captured operation, then confirm the resulting membership before updating its button. Removals retain their own records so an older peer list cannot silently add the title back. Existing authenticated lists seed only missing titles and do not override newer edits or removals. Adding beyond 1,000 titles reports a capacity limit instead of deleting an older title. Android's integrated gateway also checks the captured register revision, rejecting an older edit even within the same account and profile. Cross-language fixtures check the shared item representation; physical cross-device convergence remains a final acceptance check. Remote Trakt/SIMKL lists keep their own existing behavior.

**Previously watched episodes are migrated from evidence, not guessed.** Some older accounts store watched episodes as compressed bitmaps rather than explicit episode IDs. The new migration decodes them against episode inventories from the original configured provider, tied to the exact account, profile, verified user, source and row. It retains the original encrypted snapshot and accepted evidence. If that original provider is unavailable or ambiguous, history remains visibly pending with a Retry action instead of being converted to empty history or fabricated progress. Historical retry continues to use the original source even if the current account configuration has changed; recovered history cannot be imported into the replacement account. Both Apple and Android journal/retry hosts are integrated. A pending independent-account connection preserves the currently active binding and can resume after restart using its exact retained credential transaction.

**Cinema keeps the useful routes together.** Apple Home, Browse/Search, Library, Watchlist, History and Downloads use a consistent hierarchy on iPhone, iPad and Mac. Quick View exposes Watch Now, Add to Watchlist and Details without hiding its actions below the initial phone viewport. Catalog and Continue Watching cards retain artwork, ratings, facts and synopsis; episode details retain their fuller metadata. Source badges wrap on narrow phones, and source groups stay readable when you jump between add-ons. Mac retains horizontal navigation, a visible Search field, native close/minimize/zoom and one detail Back.

**Android touch and TV gain the same Cinema navigation structure.** Featured Home and Browse can share a destination while preserving the separate-Browse preference. See All opens the selected Home row, including client-generated rows and paging. Library exposes Downloads, Watchlist and Previously Watched routes without replacing saved membership with playback history. Continue Watching cards keep a typed, one-shot resume action and fall back to Details when that device has no matching saved stream. Android TV restores the invoking shelf or Library entry when returning from a depth route, and its ordered source tabs jump to the chosen add-on section while retaining nearby groups. The combined production-source cohort compiles and passes its focused tests; final optimized package compilation and physical D-pad/focus acceptance remain release gates. Isolated source fixtures do not establish every TV interaction.

**Each profile can control which add-ons it sees and how their sources rank.** The per-profile visibility and ranking settings inherit the account defaults until that viewer explicitly changes them. Disabled add-ons remain scoped to that profile; accepted configuration changes retain the captured account and profile. Reordering or replacing add-ons is committed as one ordered change, and a failed or stale operation cannot publish a misleading successful list.

**Website add-on edits have a durable, account-bound acknowledgement path.** Deliberate install, remove and reorder actions now have a versioned causal contract with the native core and both hosts. The hosts checkpoint the exact event and its matching receipt before acknowledging it; an old baseline or a receipt belonging to another account/profile cannot stand in for the submitted edit. A newer native removal or account change remains a visible conflict instead of being presented as successful restoration. Unsupported or rejected work stays pending without blocking independent valid changes. The reviewed matching website uses native state as its authority after migration, rather than the preserved legacy list. It also checks known optional manifest fields before queueing a descriptor the native decoder cannot consume, while retaining valid defaults and unknown extensions. The matching source is deployed and its production assets are verified; authenticated multi-device convergence and live Stremio-account import are still separate acceptance checks.

## What's fixed

**Continue Watching prepares the next episode for the exact viewer and episode.** Apple now connects Continue Watching episode navigation to bounded next-episode source preparation. The work captures the active profile, account, episode, source generation and chosen release before it waits. Leaving the route, switching viewer, changing source or replacing the account retires the old result. The next episode can reuse a valid prepared source; an expired or superseded preparation is rejected before loading. Host-side preparation and admission are bounded. The integrated native NNTP lease/cancellation paths still require the fresh combined app/runtime and provider acceptance below.

**Native Apple Home keeps the selected Trakt Continue Watching source.** Home on Apple TV/iPhone/iPad and Top Shelf now use one profile-scoped read selection instead of native mode unconditionally replacing an eligible viewer's saved Trakt choice with local rows. Native history remains the local fallback and authority for each profile; an unavailable native session cannot borrow a retired legacy overlay. Private artwork publication retains the captured native account/profile and Trakt session, so an older warmup cannot publish into the replacement viewer. This repairs the read-selection/publication path, not unverified live Trakt progress delivery.

**A fresh show starts with regular episodes rather than specials.** The default Play target and initial episode-list season now prefer season 1 or the first regular inventory instead of the season-zero special that happens to sort first. A manually selected special, an exact Continue Watching target and a resumed special remain authoritative. Shows containing only specials still work. This addresses the default-selection part of [#244](https://github.com/VortXTV/VortX/issues/244); it does not establish automatic watched tracking after returning from Infuse.

**Binge playback remembers the audio language actually selected.** Accepted in-player audio changes update the captured series choice. Next-episode selection and warming prefer a compatible source while retaining the chosen add-on/release tie-break. A delayed track inventory from an outgoing load cannot teach the next episode the wrong language. If compatible metadata is unavailable, preparation can defer or fall through to allowed alternatives rather than silently presenting an incompatible warmed choice as confirmed.

**Pause survives an accepted source or player replacement.** A same-media replacement carries the viewer's paused choice into the newly mounted engine. Old recovery callbacks cannot turn it into an unsolicited Play, and a rejected replacement does not alter the current player. A newer explicit Play, a different episode or an obsolete mount cannot inherit the previous pause handoff. Existing preview return continues to restore the original owned position and pause choice.

**A pending seek keeps its accepted target through recovery.** AVPlayer recovery retains the target that the current seek actually owns instead of losing it during a slow reopen. Queued mpv property/restart samples are fenced to the issued source and generation; an optimistic reported target is not treated as completed playback recovery. Manual seeking continues to retire an older automatic resume. Resume at zero and the opening seconds of local NNTP playback retain their real ownership and position rather than being converted into a generic restart.

**Native Dolby Vision startup on Apple TV gets its actual decoding window.** A retained TV diagnostic revealed an initiating timing defect: loading the MP4's display metadata took over ten seconds, and the old ten-second startup timer demoted AVPlayer in the very same instant its item finally attached. The item never received an opportunity to decode. Metadata preparation now has its own bounded deadline and same-item attachment without fabricated display criteria if that deadline expires. The unchanged ten-second active decoding allowance begins from the exact item's real attachment, not from the earlier metadata request. Late metadata, an old source, terminal failure or Stop cannot reattach the retired item, and pause intent is preserved. This repairs that corroborated pre-attachment race, not every Dolby Vision rejection or stream stall.

**HLS startup no longer parks its producer before the first playlist can be ready.** A reproduced high-bitrate path reached the steady-state 160 MiB forward limit with only about eight seconds produced, before the initial twelve-second playlist cohort was complete. Startup now temporarily borrows the unused history share, allowing up to 288 MiB ahead inside the existing physical budget. The grant ends on durable master publication or an admitted real positive playback receipt, restoring the unchanged 160 MiB ceiling and 136 MiB resume line. It is not renewed by seeking, pausing or adopting prepared playback. Preparation also requires an actual closed-boundary park receipt, not merely a requested pause. This fixes the demonstrated startup reservation/readiness deadlock without extending readiness timing, increasing the 1 GiB physical cap or promising that arbitrary oversized media boundaries will fit.

**mpv cache recovery reads the native cache state that actually exists.** Cache statistics are now decoded from libmpv's typed cache-state map. The previous slash-property reads returned unavailable on the pinned player, hiding the low-level seek counter and preventing some bounded memory-pressure recovery from being admitted. A reanchor now requires the actual native counter and current source, command and pause ownership; an optimistic position alone cannot confirm it. The recovery remains bounded, preserves pause and restores the original cache option after success, rejection, cancellation or timeout. This fixes the measured cache-state/admission defect without changing decoder policy or promising unlimited throughput.

**mpv preserves complete request-header values when switching sources.** Commas, quotes and backslashes in sanitized add-on headers no longer pass through a comma-separated option parser that can split a single field. The player sets a typed header array in deterministic order and clears fields that do not belong to the next source. Final header admission happens before retiring the current source's load, pause, cache-recovery or display bookkeeping; a rejected header option does not dispatch the replacement. This repairs the reproduced property/admission path, not a claim that every redirected AIOStreams or TorBox stream, hardware decoder or HTTP range response is fixed.

**A source-specific User-Agent cannot become the next source's default.** The shared Apple mpv controller now uses the same immutable configured Safari identity at initial setup and whenever a later source omits its own User-Agent. Previously, a lazy read could capture the first source's custom or trailer identity and restore that wrong value on subsequent loads. Nil headers, an empty header map and an empty User-Agent now restore the configured default while clearing the old referrer and header list; explicit source and trailer identities remain supported. This fixes the reproduced cross-source identity leak, not an explanation for first-source AIOStreams failures or proof of provider, redirect, HTTP-range or decoder behavior.

**Terminal errors cannot restart an old item underneath the error screen.** Apple TV recovery now also fences queued property callbacks after terminal failure. Retry remains tied to the episode that failed to resolve, including timeout, duplicate outgoing-source and rejected-command cases. Later native recovery work cannot dismiss the useful error or quietly start the previously played episode. Explicit Dolby Vision-remux Off still takes precedence over display defaults and remote configuration.

**Subtitle background choices affect the actual mpv subtitle renderer.** The existing background styles now drive the rendered subtitle box instead of being only an interface preference. Track selection, timing, styling, file-matched add-on subtitles, pinned transport and native overlay behavior remain available. Player accent controls stay inside their control shapes, and Reduce Transparency gives those controls an opaque presentation.

**Paused external captions stay on the source timeline after remux resume.** Activating an external subtitle or changing its sync offset now immediately refreshes the cue using the achieved remux origin, not just the replacement player's local clock. The right cue appears while paused without waiting for a periodic tick, seeking or resuming playback. Direct native playback retains its zero-origin behavior, and native subtitle fallback remains untouched while external captions are off.

**An explicit Stremio reconnect can restore deliberately imported add-ons.** On Apple, owner and shared-account sign-in now imports the authenticated account's add-ons additively into the native roster, including a previously removed same-URL add-on, rather than only updating the account model. The import retains the selected account, profile, credential and source authority through its durable commit. Passive authentication/recovery does not perform that explicit import and must not resurrect removed add-ons. If the connection saves but the import cannot be confirmed, the app reports that distinction and asks for refresh/retry rather than claiming success. This repairs the native explicit-import path behind [#205](https://github.com/VortXTV/VortX/issues/205); final account/device acceptance remains separate.

**Native NNTP read-ahead now works concurrently at the actual media boundary.** The identified bottleneck was in the logical media pump: it acquired articles serially through small reads even though the underlying session supported concurrent work. It now warms bounded article batches through the same single-flight and validation path. A seek cancels the older warming generation before waiting for the new read, and stale completions cannot restart it. Nearer useful playback coverage is kept ahead of farther speculative articles; cold archive caches are reclaimed before recently used playback caches; contiguous cached coverage stops at a real hole. The unchanged four-connection default keeps background work bounded and leaves headroom for a foreground read under the unchanged memory budget. This repairs the proven scheduling defect. Fresh packaged-runtime acceptance and provider throughput remain separate checks; it does not guarantee that every NNTP provider or connection can sustain every bitrate.

**Apple NZB eligibility uses the selected runtime instead of requiring a legacy listener.** The integrated admission gate lets a supported native Full target attempt bounded local startup with configured saved providers or validated add-on server hints, even before its native endpoint has been published. It does not borrow a legacy listener when native mode is selected, start a process while ranking sources, or make Lite/missing-runtime local playback appear available. The existing remote TorBox path remains independent. This fixes source eligibility; the reviewed operation/selector paths remain subject to whole-app/runtime and device gates below.

**Android Usenet routing preserves the source's provider and mirror inputs.** The reviewed integrated path carries add-on-supplied NNTP servers and NZB mirrors into scoped native operations, retains the ordered saved-provider fallback, and respects an intentionally confirmed cached TorBox selection. Caller cancellation or an account/profile change retires owned work rather than publishing its late result. This replaces the native path's old Kotlin routing, beyond the earlier admission-only overload. Its secure indexer factory captures the actual active profile and fails closed when the roster is unknown; integrated configured-indexer results also retain that captured account/profile and configuration revision. A search result is not presented as confirmed cache availability. Final app/package and real-provider acceptance remain separate.

**Apple playback and downloads retain the Usenet operation they actually own.** The reviewed producer captures its original account/profile coherently before asynchronous server warmup and retains the operation through the accepted playback lifecycle. The reviewed download consumers carry that captured native operation through individual and batch download handoffs instead of dropping its lease at source resolution. Cancellation, removal and replacement retire owned work; an older completion cannot be transferred into a new playback/download owner. Producer and consumer changes are immutably reviewed and integrated, with the combined canonical source cohort accepted; freshly packaged runtime and physical acceptance remain pending.

**Local NNTP starvation recovery is bounded on Apple TV.** The player distinguishes genuine repeated starvation from ordinary buffering and uses same-source recovery with the retained resume target. It does not repeatedly erase useful cache or restart forever. The native transport tests exercise cancellation, foreground admission, socket reuse, exact range/EOF bytes and retirement. Compressed or encrypted archive reconstruction and PAR2 repair remain unsupported; larger buffering settings do not change those limits.

**Fresh MPV/FFmpeg build inputs replace the old dependency package.** The selected Apple MPVKit artifact has rebuilt FFmpeg 9 libraries, the retained Dolby Vision split capability, and Apple SecureTransport for HTTPS. It also includes the reviewed Mac CoreAudio initialization-failure lifetime repair: failed setup no longer leaves device listeners pointing at an already released output context. Artifact checks cover the required Apple slices, architectures, deployment floors and linking dependencies. These are dependency/content and lifecycle repairs; Dolby Vision output, audio routing and decoder behavior still need the final app and physical display/receiver checks.

**Native Apple packages receive typed provenance fields in their actual plists.** The project generator now preserves each target's existing plist values while writing the native-engine, resource-host, exact-source and transport markers into a target-specific generated base plist. Build settings alone had not emitted those markers into the explicit base plists, causing a later Apple candidate to fail its provenance gate before launch. This repairs package generation, not final IPA, launch, signing or device acceptance; fresh artifact and whole-app gates remain pending.
