# Apple playback and state audit — 11 September 2026

Scope: the 12,234-line diagnostic spanning 10–11 September, including its duplicated always-on and server tails. Four disjoint log reviews covered every line. This is not the earlier diagnostic with the same filename. Raw logs and account/provider identifiers are not included in this repository.

## Implemented

- **tvOS receipt storage:** successful source contributions previously persisted up to 40,000 SHA-256 receipts in UserDefaults, exceeding tvOS's 1 MiB preferences limit. Six SIGABRTs in the diagnostic immediately follow successful contribution replies. The store now uses an atomic file, verifies legacy migration before retiring the large defaults key, and retains a small marker so an OS cache purge cannot silently reset deduplication. The actual device receipt count and complete assertion text were not recorded, so the platform-limit defect is established but the exact crash assertion still needs device confirmation.
- **Player-switch resume:** the current episode's active origin now wins over immutable launch arguments. The diagnostic showed a switch near 30 seconds remounting at zero, and another episode's switch near 15 seconds incorrectly reusing the original CW offset near 2,590 seconds.
- **AVPlayer deferred Play publication:** resuming a recovery that was deliberately deferred while paused now publishes the resumed transport intent before returning. Previously only ordinary Play did that; while the remux recovery remained at rate zero, KVO could not update the pause indicator. This fixes that concrete state-publication gap, not every cause of remux starvation.
- **Remux display range:** mounting a remux no longer automatically requests Dolby Vision. The display request follows actual DV signaling or PQ/HLG/SDR metadata; explicit HDR fallback remains HDR.
- **CW episode refresh:** a valid empty unloaded model now completes the invalidation phase, including when Unload emits no event. Malformed snapshots are not treated as unload receipts. Refresh and re-find callbacks are generation-fenced.
- **Canonical episode metadata:** both CW launch and EOF navigation refresh accept a canonical metadata ID for the exact selected request and episode. This does not grant title-finality authority or remove a series from CW.
- **Watched marks during refresh:** temporarily missing metadata no longer immediately discards an episode-completion intent. A bounded five-minute queue retains the exact episode and account/profile owner, replays on matching metadata, and respects subsequent explicit unwatch actions. Series completion never substitutes a whole-title watched mutation.
- **Add-on/source order:** loaded source groups now use the same persisted order as the add-on UI. Reordering invalidates the live source-list cache. New/unlisted add-ons remain visible in stable order.
- **Add-on roster snapshots:** typed and raw descriptors come from one engine snapshot; decoding failure retains the last valid roster instead of publishing an empty one.
- **Cross-device order echoes:** an unrelated push previously overwrote a freshly fetched peer order with this device's stale applied order, and a partial engine snapshot could shrink that order. Only an explicit, account-scoped reorder now overrides the cloud field. Persisted nonce-bearing intents survive network failures and restart; acknowledgements clear only the sent intent, so a newer edit or undo remains pending. Derived pushes are serialized per credential scope, and remote-only entries are preserved. Concurrent explicit reorders use last-successfully-pushed-intent precedence; older unpatched clients can still overwrite the field, and the existing backend version high-water is not a true conditional-write CAS.
- **Removal/reinstall receipt rollback:** cloud settings restore used to replace add-on and library timestamp maps as scalar preferences before the semantic fold. It now preserves local per-entry maxima across the restore, including when an older blob contains empty/stale maps. Manual file import remains an explicit restore. Cloud add-on descriptor unions now deduplicate using the same normalized URL identity as order and removal records.
- **Mirror-off local add-on mutations:** account hydration used the ordinary engine install action, which could publish an authenticated Stremio add-on collection even with mirroring disabled. The reviewed engine pin provides local-only install, uninstall, and atomic replace actions. Account hydration always uses the local action; explicit mutations and tombstone cleanup select local actions when mirroring is off. Routine refresh no longer pulls the Stremio add-on collection with mirroring off; explicit import remains available.
- **Atomic URL replacement:** Change URL no longer installs and then separately removes the old descriptor without a removal receipt. It rejects protected/unconfigured descriptors and an already-installed different target, confirms the new entry and old entry's disappearance, then replaces the old priority slot and records its removal. Same-URL refresh no longer pre-uninstalls the working descriptor.
- **Warm account hydration:** a settled account pull now materializes missing owned add-ons from that exact document. An equal-version, current, fully-applied document can repair a partially populated engine; forced equal-version first restore still performs its full apply. Lower versions and stale credentials are rejected. There is no second GET for this warm path.
- **Preview lookup storm:** the diagnostic's 1,057 repeated missing-runtime lookups during one CW run are replaced by an in-flight fence and failure backoff. Real player duration supersedes provisional runtime, and stale tasks cannot reconfigure a replacement load.
- **File backup restore:** profile state is reloaded before catalog/discovery projections, preventing the stale live profile from overwriting restored row order. The account-sync roster-union path is unchanged.
- **Decoder diagnostics:** use mpv's real codec and pixel-format properties and sample at video reconfiguration. This improves evidence for software fallback; it does not claim to fix unsupported decoding or frame drops.

## Playback follow-up — after the beta 11 source cut

The user reports that duplicated/triplicated AVPlayer subtitles were absent in the last device test. Preserve that improvement; the remaining reported subtitle styling defect is the built-in background.

- **Built-in subtitle background:** set both Core Media background attributes explicitly. The enclosing text window is transparent; the user's outline/shaded/box selection still controls the character background. Foreground styling and the single native renderer remain unchanged. Actual AVFoundation styling precedence, authored/bitmap subtitles and accessibility preferences can still affect device output.
- **AVPlayer rewind versus old EOF:** a new explicit seek discards the previous paused EOF and cancels its tail-recovery task. Event-owned recovery receipts now include the seek revision, so old same-item work cannot replace a newer requested position. Genuine producer errors are not erased.
- **AVPlayer seek liveness:** only actual admission/native seeks enter the end-notification fence; pre-ready targets do not. A request/item/token-owned 12-second completion deadline aborts blocked admission before cancelling the native seek, then uses the existing target-owned remount transaction. It preserves committed pause/track intent and never fabricates an episode EOF. Normal completion cancels the deadline. This is not a longer mid-play stall watchdog.
- **Remux producer reanchor:** a successfully completed seek immediately updates the producer from the actual player landing while holding the receipt lock. A paused landing no longer depends on another periodic tick to reconcile the lead/byte ledger. Stale or duplicate completions cannot mutate that ledger.
- **libmpv repeat/slow seeks:** a seek with an observed landing no longer permanently marks later seeks ambiguous. The one-shot reopen window starts at the first post-seek position receipt, not before a potentially long network wait; later ticks cannot renew it. An observed mid-file seek with no landing remains protected against false episode completion after five seconds. Untagged overlapping seeks retain their conservative ownership checks.
- **Native-provider recovery and engine switching:** a late frame from the still-mounted item cannot cancel an in-flight fresh-link request on tvOS or iPhone/Mac. Apple AV-to-mpv switching now checks fresh-link recovery before physical demotion. A user can reverse a pending engine choice; selecting the already-mounted engine reloads the accepted fresh URL instead of silently dropping it. Stale provider results retain their existing generation/source/token fences.
- **NNTP actively transferring articles:** the former absolute 20-second timeout could discard a continuously downloading article. Nonempty article data now renews the inactivity timer; an independent overall safety bound and the existing 64 MiB article cap remain. Success, failure and cancellation retire both timers. Reapplying the patch upgrades an already-v1-patched generated server rather than silently shipping its old worker.
- **Android adaptive-trailer audio:** set/clear the `audio-files` list before loading the new video, preserving each URL as one argv element. The previous immediate post-load `audio-add` could race the outgoing/initializing file. This addresses split-audio sources, not every Android audio report. See the [mpv audio-files and command reference](https://mpv.io/manual/stable/#options-audio-files).
