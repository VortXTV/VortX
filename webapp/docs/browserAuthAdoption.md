# Browser auth adoption — local source milestone

The scoped auth successor is integrated and locally verified through actual-source unit tests and the existing strict project type gate. This is not native-browser, live-account, data-cutover, app-build or deployment acceptance. Earlier frozen candidates and failed gate attempts remain historical evidence; they are not relabeled as passing.

## Authority and persistence

Vault owns one realm revision and private admission/proof records. Account consumes it and retains a known blocked owner as an account, never as a guest. All cooperating credential writers use the existing key formats and one exclusive Web Lock `vortx.session.writer`. Inspection is pure and makes one descriptor/tab-slots/confirming-descriptor observation. A changed confirming descriptor returns unavailable immediately, even if A returns before a possible retry; pure load can return null without changing authority. Actual admission/ownership gates retire the witnessed failure. Owned legacy migration is explicit. Network, crypto and UI callbacks never run inside the short storage lock. A notification delivers a stable listener snapshot; a retired Login subscription ignores a later callback.

Each attempt captures exact descriptor/tab-key/legacy bytes. The consequential request rechecks that preimage after preparation; an observed foreign or denied preimage permanently retires earlier capabilities even if A's bytes return before any storage event. This is witnessed retirement, not detection of unobserved ABA. Admission, explicit legacy migration, local completion, explicit memory choice and accepted setup resume use the same witnessed-failure rule, including post-proof rechecks. Migration binds its first inspected legacy candidate to the exact subsequently admitted pair; owned nonlegacy and true guest-empty migration remain no-write no-ops. Local completion proves the captured predecessor before deriving same-owner metadata, then rechecks inside the lock, stages the tab key, publishes the descriptor and verifies exact readback. Lock-held witnesses notify only after the callback exits. Conditional compensation can restore only its still-owned tab slot, never a shared rival descriptor. A read witness retires permissions even when exact compensation proves nonpublication; an ordinary write exception with a readable exact predecessor is not by itself an ownership witness. Verified publication is recorded before observers. Persisted, explicit memory-only, not-persisted, retired, unavailable and uncertain are distinct outcomes. No unlocked durable fallback exists.

Readable empty storage plus original guest/memory provenance is required for explicit memory adoption. Read denial, former persisted ownership, malformed/future/unowned material and residual logout bytes do not grant it. Logout retires volatile authority immediately and cannot silently re-adopt its failed-clear descriptor. Hydration, receives, queued settings and the narrow household consent capture use the same authority guard; retaining known A does not authorize effects after A→blocked B→A.

## One-shot remote work and current effects

A private invocation latch is claimed before async preparation. The first dispatch owns immutable prepared key/code/request evidence; duplicate invocation or dispatch cannot replace it. Raw OTP/password inputs are not added to persistent storage or diagnostics. An irreversible slot is reserved before preparation and retains unknown or accepted material. Never automatically repeat an unknown request, mint a substitute key/code, or claim rollback.

Endpoint-specific documented status/error combinations alone release the slot as rejected. Unrecognized or malformed responses, transport loss and failed/unconfirmed server outcomes remain unknown. An accepted reset is attached before its existing proof-finalization step; no new proof contract is introduced. This classification is based on source contracts, not live account/backend verification.

Explicit accepted setup resume and local ambiguity resolution create a fresh private admission. They share only retained payload, recheck owner/preimage/retained identity across proof awaits, and leave old tokens permanently retired with their own historical result. A queued commit cannot be retargeted by competing resume. No remote request is repeated. Current effects/code access require the successor receipt and live surface.

Login updates a guarded pending/action region without replacing the current form or dropping entered intent. It shows a keep-tab warning from operation start, only an eligible accepted Resume control, a local-uncertainty resolve control, and a separate eligible explicit memory choice. Unknown remote work gets a no-repeat warning, not a replay control. Route/owner retirement still scrubs current secret DOM and fences username/clipboard/approval completions.

## Scope and limits

Production scope is the original six paths (vault, account, Login, approval, main, Settings signout) plus only household's consent ownership capture. No household data protocol/schema change, new management UI, IDB caller port, data adoption/export, credential provisioning or automatic logout/reset was added. Regenerate-recovery-code and 2FA enrollment remain unported setup workflows with no current production caller found.

Explicit per-realm bounds: one active UI attempt, one queued/current credential commit, one retained irreversible operation, one uncertain commit and one failed-logout evidence record (some may alias); one coherent observation per inspection; one original 10-second pre-entry lock deadline; existing 15-second transport deadline. Arbitrary unknown JSON metadata is preserved, not truncated. No byte/RSS/GC/constant-time bound is claimed for metadata, crypto, returned snapshots or caller-held tokens.

Participating-client Web Locks do not fence old noncooperating writers, undelivered cross-tab ABA, cross-store power loss or tab destruction. Unknown private material may be lost with the tab; no plaintext journal/export was introduced. Native lock/storage/quota/DOM behavior, browser-data/W1 cutover and deployment remain HOLD.

## Verification and saved schedules

The successor has 33 actual-vault/account/household groups and 12 actual-Login/Settings/approval groups (45 top-level tests), with explicit synthetic storage/lock/DOM/transport schedules. The original public Login missing-persistence ingress remains unchanged in intent and requires no proposed export on its negative-control path.

Added saved schedules cover finite listener delivery; no-event pre-POST mismatch; twin invocation and original code/key; old-token resume/resolution; held commit and proof-await races; blocked household ABA; endpoint rejection/unknown controls; original lock deadline; rival compensation; already-durable no-op; password/QR pre-send retirement; same-form accepted-save/proof recovery; unknown warning; username query and clipboard retirement. Eight witnessed-boundary groups cover no-event restoration after admission/migration/pre-metadata/lock-entry/staged-read/readback/memory/resume witnesses; deferred notification; same-owner versus cross-account metadata; definite quota failures versus observed read failures; accepted-candidate resume; and preserved accepted reset proof. One further group exercises torn A/keyA/confirmB then restored-A reads at begin/completion, alongside pure-load and unchanged-authority controls. Earlier pair/phase/readback, failed logout, explicit memory, nested metadata, hydrate/receive and route/TOTP tests remain.

Nine existing fixture suites are adapted without a production admission backdoor: storage, writer ownership, CAS, reset-generation, account ownership, settings, continue-watching, realtime and household account-fence. Actual login/completion admits synthetic owners; exact raw seeding is limited to owned boot or adversarial peer fixtures. Genuine memory tests explicitly choose memory-only. Reload fixtures retire old callbacks and load a fresh production graph over preserved synthetic durable bytes. Account-owner assertions distinguish retained identity from denied permission; old in-flight ratchet responses must now reject without raising even the old floor.

The household orchestration suite still mocks its vault dependency and is labeled as such; the new blocked/ABA regression imports the actual graph. Fake DOM/locks are not browser proof. These saved cases are not exhaustive browser interleaving or arbitrary quota/engine-failure coverage.

### Observed local results

Verification used serial, complete per-file source-unit commands, not one full package-chain invocation. The accepted-source result comprises 33 test-file commands with 362 registered cases: 361 passed and the existing website-only restore case was skipped in app-web. This includes all 45 new auth tests and the complete 47-case realtime file. The unchanged strict project configuration completed no-emit checking with zero diagnostic bytes; the Pages contract check also completed normally.

The original public Login missing-save regression failed with the intended persistence assertion against the original source, then passed in the complete successor form suite. Its old wrapper remains failed because its prepared selection counters differed from Node's actual reporting; only the attributable assertion is negative-control evidence. A separate early type attempt found an unused private function, which was removed without changing compiler options. Another attempt exposed a fixture-lifetime error: it re-admitted the old subscribed realm immediately before simulating a reload. The corrected fixture seeds already-owned boot credentials only after retiring that realm. The replacement complete realtime run passed without changing the 350-ms retry or 30-second ownership lease.

The 34 individually successful unchanged commands from the earlier batch are retained as per-file evidence; its failed realtime command and the earlier failed batches remain failed. The correction-only run replaces the entire realtime file's result, not just its failed nested case, and does not replay successful suites. Source, execution-input and tool consistency was checked at the recorded precommand and postcommand points. Command nonces, normal exits and owned cleanup were verified from retained receipts. This composition is bounded local source evidence, not proof of real browser scheduling, storage/quota behavior, deployed account recovery, W1 cutover, RSS or device performance.
